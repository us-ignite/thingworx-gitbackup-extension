# Mashup sources

`Mashups_GIT.Mashup.Home.xml` uses a Collection widget to map repository Things to `GIT.Mashup.RepositoryRow`,
which provides Changes, History, Branches, and Settings actions for each row, and links to Git User Settings. It is
the default item in the Git menu. `src/HomeNavigation.ts` is embedded during
packaging by `embedHomeNavigation`.

`Mashups_GIT.Mashup.RepositoryCreate.xml` is the New Repository form, opened from the **New repository**
button in the Home header. It collects the repository name, remote URL, initial branch, storage path,
optional credentials and signing key, tracked projects (from `GetTrackableProjects`), and proxy and
localization options, then calls `RepositoryCreate`. A signing key is applied afterwards with
`SetGPGKeyForSigning` on the new Thing. On success it opens Repository Settings for the new repository.
`src/RepositoryCreate.ts` is embedded by `embedRepositoryCreate`.

`Mashups_GIT.Mashup.RepositorySettings.xml` edits the current user's credentials,
committer identity, and signing key for the selected repository. A blank password
keeps an existing password. `src/RepositorySettings.ts` is embedded by
`embedRepositorySettings`; the user-level Settings mashup manages reusable GPG keys.

`Mashups_GIT.Mashup.Changes.xml` uses the repository selected on Home and provides working-tree
status, selected-file stage/unstage/untrack actions, Remove Source Files, Remove from Everywhere, and
staged commit. Untrack, Remove Source Files, and Remove from Everywhere use confirmation dialogs.
Remove Source Files deletes the selected files and stages tracked deletions, but leaves ThingWorx
entities in place. The Git Changes menu item is in
`Menus_GIT.Menu.GitBackup.xml`.

Every page except Home embeds `GIT.Mashup.GitHeader` in a `git-header-slot` container. The shared
header shows the Home breadcrumb, an optional User Settings crumb, an optional repository crumb, the
page name, and the current branch. It takes these mashup parameters:

| Parameter | Type | Effect |
| --- | --- | --- |
| `repoName` | STRING | Repository Thing. When set, shows the repository crumb and reads the branch through `GetCurrentBranch`. Leave blank on Settings and Extension Log. |
| `pageName` | STRING | Current page label. Set it statically on the Contained Mashup. |
| `showUserSettings` | BOOLEAN | Shows a **User Settings** crumb that links to `GIT.Mashup.Settings`. Used on Extension Log. |

`src/GitHeader.ts` hides the repository crumb and branch when `repoName` is blank and calls
`GetCurrentBranch` only when a repository is set. It is embedded by `embedGitHeader`. Changes and
Branches call the header's `Refresh` after relevant Git operations; the header's `RefreshRequested`
event reloads the branch. After saving a page in Composer, check that `git-header` still has its
`pageName` and flags. The Extension Log entry point is a card at the bottom of User Settings, not a
header action.

## Shared styling

`src/Shared.css` contains the styling foundation for Home, Repository Row, and
Changes; `src/Home.css`, `src/RepositoryRow.css`, and `src/Changes.css` contain
their page-specific rules. Edit these files rather than the corresponding
`CustomMashupCss` fields in the exports. Run
`./gradlew :apps:thingworx-jgit-extension:embedMashupCss` to embed them;
packaging runs the task automatically. The mashups retain the active ThingWorx
theme for widget colors and focus states. Check layout and theme compatibility
in the target runtime, including the repeated Repository Row collection.

## TypeScript helpers

For the export's XML, embedded JSON, and binding structure, see
[mashup-format-primer.md](../docs/mashup-format-primer.md).
For the widgets, extension dependencies, Java data model, and UI editing
workflow, see [ui-agent-guide.md](../docs/ui-agent-guide.md).

`src/GitHelper.ts` is the editable source for the `GitHelper` class host in the
Branches mashup. The `BMTypescriptClassHost` uses ThingWorx binding decorators
and evaluates the generated `TranspiledCode` at runtime. The build embeds the
TypeScript source fields and transpiled JavaScript.

Run `./gradlew :apps:thingworx-jgit-extension:embedGitHelper` to update the
export after editing the source. Packaging the extension runs this task
automatically. The task uses the pinned TypeScript compiler in this directory's
`package-lock.json`; npm and Node.js must be available.

The `src/types` declarations are synchronized from the pinned BMCoreUIWidgets
release ZIP. `tsconfig.json` includes them for editor language services,
including the ThingWorx widget decorators and global types such as `STRING` and
`TWEvent`. Run `./gradlew :apps:thingworx-jgit-extension:syncUiTypeDeclarations`
to refresh them; helper embedding and extension packaging run this task too.

Treat the files under `src/` as the sources of truth. Do not edit a mashup's
`Code`, `Exports`, `TranspiledCode`, or `CustomMashupCss` fields by hand; those
fields are regenerated by the embedding tasks.

## History mashup

`Mashups_GIT.Mashup.History.xml` uses the repository selected on Home and `GitHistoryWidget` to browse commits, changed files, file contents, and diffs.
Build the distribution with `./gradlew :apps:thingworx-jgit-extension:packageExtensionPack`.
The resulting pack contains five independent ThingWorx extension ZIPs, including
the MonacoScriptEditor widget. Install
BMCoreUIWidgets, agGridWidget2, and GitHistoryWidget before JGitExtension; the
pack itself is a distribution archive, not a ThingWorx import ZIP. Composer
validation and viewing the mashup on the target ThingWorx version are needed to
verify bindings and layout.

The Monaco ZIP provides a mashup widget; replacing Composer's script editor
requires the separate browser userscript described in the [upstream installation guide](https://github.com/thingworx-field-work/MonacoEditorTWX#installation).

## Log and Reflog mashups

`Mashups_GIT.Mashup.Log.xml` lists commits from `GetLog` for the selected ref, or for every branch
and tag with **All branches**. `Mashups_GIT.Mashup.Reflog.xml` lists local reflog entries from
`GetReflog`. Both pages use the repository selected on Home, embed `GIT.Mashup.GitHeader`,
fill their Ref selector from `GetHistoryRefs` (`ReflogOnly` on the Reflog page), and reload when
the selection changes. Each grid's `GridConfig` names, sizes, and hides columns; column order
follows the data shape. The History page and the Git menu link to both pages.

## Extension Log mashup

`Mashups_GIT.Mashup.ExtensionLog.xml` lists entries the extension wrote to the ApplicationLog,
using `GetExtensionLog` on `GIT.Utility.Thing`. It is opened from the **Open Extension Log** button
in the card at the bottom of Git User Settings, and its shared header links back to Home and User
Settings. The grid's column filters handle level and message filtering.

## Branches mashup

`Mashups_GIT.Mashup.Branches.xml` is a standalone branches mashup. It copies the
branch section of the operations mashup: current-branch status, branch create
(with optional start point and checkout), branch switch, branch delete, branch
list, and branch operation status messages. It is linked from the repository row
on the Git Home mashup through the repository row's Branches action, which uses
a native Navigation function and binds the repository name to its target. Build the
distribution with `./gradlew :apps:thingworx-jgit-extension:packageExtensionPack`.
The branch switch service accepts a force parameter, and the mashup exposes a
"Force checkout" checkbox that binds its state to that parameter. **Delete
Branch** refuses a branch with commits that are not merged into the current
branch. **Force Delete Branch** opens its own confirmation, then calls the
`BranchDeleteForce` service instance (`BranchDelete` with a static
`Force: true`), following the Changes mashup's `ForcePull` pattern. Composer
validation and viewing the mashup on the target ThingWorx version are needed to
verify bindings and layout.

## Merge and conflict resolution

`GIT.Mashup.MergeControls` is embedded in a card at the bottom of Branches. It lists local and
remote refs, starts a merge or rebase, and offers **Resolve Current Conflict** when the repository has a paused operation.
The button opens `GIT.Mashup.ConflictResolution` for the same repository. The Changes operation-result popover also links to the
resolution screen when an operation reports a conflict. The resolution screen
loads conflict state and file versions, stages a selected resolution, and can
continue, abort, or skip a rebase commit when the service permits it. Binary
files can be resolved by selecting an existing side or deleting the file.

The editable helpers and styles are `src/MergeControls.ts`,
`src/ConflictResolution.ts`, and their corresponding CSS files. Packaging embeds
them using `embedConflictMashups` and `embedMashupCss`. Validate the contained
mashups, navigation, layout, and service calls in Composer and runtime.
